# Evaluation

Two evaluations are included. The CSIC 2010 results are the ones to quote.

## CSIC 2010 HTTP dataset

The public CSIC 2010 dataset holds requests sent to a web shop: 36,000 normal training requests, 36,000 normal test requests and 25,065 attack requests (SQL injection, XSS, command and path attacks, parameter tampering, information gathering, buffer overflow attempts and others).

Setup (`python -m ml.evaluate_csic`, files in `data/raw/`):

- The attack file is shuffled with a fixed seed and split in half.
- Training set: the normal training file plus half of the attacks (48,532 requests).
- Test set: the normal test file plus the other half of the attacks (48,533 requests, 12,533 of them attacks).
- No test request is used for training.

| Method | Precision | Recall | F1 | False alarm rate |
| --- | --- | --- | --- | --- |
| Signature rules only | 1.000 | 0.137 | 0.241 | 0.0000 |
| Classifier trained on generated data only | 0.845 | 0.197 | 0.319 | 0.0125 |
| Classifier trained on the CSIC training split | 0.919 | 0.978 | 0.948 | 0.0299 |
| Classifier trained on generated data + CSIC split | 0.932 | 0.977 | 0.954 | 0.0247 |
| Rules + that classifier | 0.932 | 0.977 | 0.954 | 0.0247 |

Time per request for the classifier: median 1.2 ms, 95th percentile 1.8 ms.

### Threshold

The score threshold sets the balance between false alarms and missed attacks (rules plus the classifier trained on generated data and the CSIC split):

| Threshold | Precision | Recall | F1 | False alarm rate | Normal requests blocked | Attacks missed |
| --- | --- | --- | --- | --- | --- | --- |
| 0.5 (default) | 0.932 | 0.977 | 0.954 | 2.47% | 889 of 36,000 | 282 of 12,533 |
| 0.6 | 0.960 | 0.961 | 0.960 | 1.39% | 501 | 490 |
| 0.7 | 0.979 | 0.932 | 0.955 | 0.70% | 252 | 850 |
| 0.8 | 0.990 | 0.884 | 0.934 | 0.30% | 107 | 1,460 |
| 0.9 | 0.997 | 0.792 | 0.883 | 0.08% | 28 | 2,602 |
| 0.95 | 1.000 | 0.659 | 0.794 | 0.01% | 4 | 4,278 |

Set it with `CHOKIDAAR_THRESHOLD`. A site that cannot afford to block real users should use 0.8 or higher and rely more on the rules.

### What the results show

- **The rules are precise but narrow.** They never blocked a normal request, but they catch only 13.7% of this dataset, because most of its attacks are not injection strings: they are tampered parameters, probes for backup files and similar requests.
- **A classifier trained only on generated data does not transfer.** It finds 19.7% of the attacks. Training data has to look like the traffic being protected, so the model should be retrained on the protected application's own traffic.
- **A classifier trained on matching data does well**, with F1 around 0.95, but the false alarm rate at the default threshold is about 2.5%, which is high for a firewall.
- **False alarms cluster on registration and edit forms**, which have long bodies with names, passwords and symbols. Raising the threshold or training on more of the application's own normal traffic reduces them.
- **Headers do not drive the result.** With all headers removed the numbers barely change (F1 0.953), so the model is not relying on header artifacts of the dataset.
- **Caveat:** CSIC 2010 is traffic to one synthetic shop, generated by scripts. Results on a different application will differ.

## Generated data

`python -m ml.evaluate` trains on 6,000 generated requests and tests on 2,000 different generated ones: precision 1.000, recall 0.990, F1 0.995, median 0.9 ms. Training and test requests come from the same templates, so these figures only show that the pipeline works and is fast. They are higher than real traffic would give, as the CSIC result for the same model (recall 0.197) shows.

## Other tests

- `tests/attacks/payloads.json` holds malicious and benign payloads for each attack type; every malicious one must hit a rule of its type and no benign one may hit any rule.
- Unseen SQL injection variants (`HAVING`, `LIKE`, comparison conditions, `WAITFOR DELAY`) must be classified as malicious, and ordinary phrases that resemble SQL (`having fun in lisbon`, `cats like dogs`) must stay benign.
- Double-encoded payloads are caught.
- The 95th percentile time per request stays under 50 ms.
